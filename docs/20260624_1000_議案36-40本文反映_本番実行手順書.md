## 4. revalidate（データ変更後に必須）

`unstable_cache`（bills 10分）とルートキャッシュのため、DB変更後に Next.js キャッシュを無効化する。
**タグは `bills` と `diet-sessions`**（両方とも `scripts/revalidate.mjs` の `ALL_TAGS` に存在）。

> ⚠️ `pnpm revalidate` という script は**存在しない**。`node` で直接実行する。
> ⚠️ `-e <envfile>` の `REVALIDATE_SECRET` と `--url` のデプロイを**必ず一致**させる（prod は `.env.prod` ＋ prod URL）。不一致は **401 Unauthorized**。

### 4-1. 推奨コマンド（リポジトリルートで実行）

```bash
dotenv -e .env.prod -- node scripts/revalidate.mjs \
  --url https://ishigaki-gikai-app-web-coral.vercel.app \
  bills diet-sessions
```

- 仕組み：`POST {url}/api/revalidate`、ヘッダ `Authorization: Bearer $REVALIDATE_SECRET`、ボディ `{"tags":["bills","diet-sessions"]}`。
- 成功時は 200 とレスポンス本文が表示される。

### 4-2. curl での同等実行（代替）

`.env.prod` の `REVALIDATE_SECRET` を使う。**prod の値であること**を確認してから実行する。

```bash
# REVALIDATE_SECRET は .env.prod の prod 用シークレットを使用（test と混同しない）
curl -i -X POST "https://ishigaki-gikai-app-web-coral.vercel.app/api/revalidate" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${REVALIDATE_SECRET}" \
  -d '{"tags":["bills","diet-sessions"]}'
# 期待: HTTP 200。
```

### 4-3. Unauthorized（401）が出た場合

- **原因の第一候補は `REVALIDATE_SECRET` の不一致**（test の secret で prod URL を叩いた等）。
- `-e .env.prod`（prod 用 secret）と `--url https://ishigaki-gikai-app-web-coral.vercel.app`（prod URL）が**同じデプロイ**を指しているか確認する。
- test/prod の env・URL を混在させていないか再確認して再実行する。

## 6. トラブルシュート / 注意

- **SQL実行でエラー**：`BEGIN; … COMMIT;` のためロールバックされる。`1-2`（bills行存在）と接続先 ref を再確認。
- **二重適用**：SQL は冪等な UPSERT（`ON CONFLICT DO UPDATE`）。再実行しても結果は同じ。
- **revalidate 401**：`4-3` を参照（secret/URL の test↔prod 混同）。
- **キャッシュが古い**：`?cb=<timestamp>` でバイパス確認。`unstable_cache` の TTL（bills 10分）でも自然回復する。
- **ロールバック**：差し替え前の最小スケルトンに戻す場合は、第2弾SQL（`docs/20260620_第4回定例会_議案本文整備第2弾_最小本文SQL.sql`）の該当 UPSERT を再適用すれば最小本文に戻せる（要・内容確認のうえ手動実行）。
